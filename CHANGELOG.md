# Changelog

All notable changes to caw-ai. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- `caw reproduce "<bug report>"` (also `--file`, or `-` for stdin): Claude reproduces a bug on its own, signed in as a test role, optionally from a test's state (`--from <test>@S3`, those steps replayed without Claude). No plan to approve, no question, no advice and no code change; Claude ends with reproduced yes, no or unclear, observed against expected, the steps, screenshots and a hint at the cause. The run folder gets `report.md` and `draft-test.yaml`, a test plan you can adopt and record; `caw/tests` stays untouched. Only on environments with `claude`, never production (`reproduce-not-allowed`), with the browser's network lock; without `writable` every write request is blocked. Exit `0` reproduced, `1` not or unclear, `2` environment (`reproduce-state` when `--from` does not reach its state). From Claude Code: `caw_start` with `command: "reproduce"`, `caw_status` names verdict, report and draft.
- Your own `caw.md` next to `prefs.json`: notes for Claude in every project, read before the project's `caw/caw.md`, which wins on a conflict, also by the Docker agent. The report and `caw doctor` name the file and its number of lines, never its content. Claude's context advice can go to either file; the card names which, and only your click writes.

### Changed
- The chat has two button sizes, actions and tools. "Learn baselines" is now "Save baselines" and looks like the other end-card buttons in every theme. Labels have no brackets any more. The workbench header is flatter and shows "caw" next to the raven.
- caw never takes user names or passwords from a page and never writes them: you fill `caw/.env` (or CI secrets) yourself. `init` asks for the role names in the terminal and lists their variables in `caw/.env.example`; `caw role add <role>` (and `caw_role add`) adds the role and names its variables, without a window; `role remove` leaves `caw/.env` as it is. A run whose role has no test user stops before Chrome or Claude start with `credentials-missing`, naming the variables, instead of opening a sign-in window.

### Security
- The page under test can no longer act as you in the workbench. caw writes the chat only into a chat frame that still has its first document and an opaque origin, checked in a script the page cannot touch; if the page removes the chat's sandbox or reloads it, the chat closes and the run ends with `chat-tampered` (exit 2). In a demonstration the page reports only the clicks, entries, uploads and keys the recorder captures itself, never notes, checkpoints, checks or ready-made targets. Keys go only to the application, not to the chat; the application frame is known by identity, not by a name the page can change. Only the application frame's own documents lose `X-Frame-Options` and `frame-ancestors`. The page may read the clipboard only while a check, `remember` or `eval` runs.
- While Claude is attached (record, a run with chat, `open`), the browser reaches only the environments, `allowHosts` and the new `thirdPartyHosts` (top level and per environment); every other host is unresolvable in Chrome and named as a warning in the run, fetch, WebSockets, beacons, iframes and redirect hops included. The Docker firewall never covered the browser; README and guide now say so.
- Chrome always runs in its sandbox; where it cannot start, caw stops with `browser-sandbox` and names the unsafe opt-out `browser.noSandbox`. The workbench no longer turns off Local Network Access; the permission goes to the application's origin only.
- Production: hosts stay blocked when written with a trailing dot or in another case; write requests are blocked to any host, sign-in requests pass only while caw signs in, and a form post into the workbench's top window is refused too. Request names keep a value with spaces as one token, and a JSON body counts as GraphQL only with GraphQL fields. WebSocket messages and production reached by IP address remain documented limits.
- Overlay: the dev server answers and bridges only the environment and itself; integrity is removed only from the application's own tags; a local build no longer serves names containing a backslash, colon or NUL.
- Everything Claude gets is masked, error messages, URLs and dialog texts included; errors arrive without Playwright's call log, and no command runs while caw signs in again. A failed sign-in fill names the field, never the value; a gate's Basic credentials are masked in `trace.zip`. README says honestly what masking can and cannot do against a misbehaving agent.
- `caw_config` no longer changes the commands caw runs (`start`, `stop`, `reset`, `ready`, `lintCommand`, overlay `start`), the environment flags (`production`, `claude`, `writable`, `allowHttp`, `insecureTls`, also by adding or removing an environment), `browser.executablePath`, `sandboxImage`, `sandboxUser` or `agent.mode`: the session makes those edits with its own Edit tool, so you see the diff. `--report junit` and `caw_init` `fromExplore` stay inside the project.
- Your Claude connection settings no longer land in the project: a private temporary file, deleted after the run, and the env values in the process environment. On Windows Claude Code is looked up on the PATH only, never in the current folder. `browser.executablePath` refuses network and `/proc` paths. Docker mount paths that would change mount options are refused. The Docker agent can no longer redirect caw's guide file through a link.
- `caw export` writes `trace: 'off'` (a trace would hold the test user's password), and a refused `goto` can no longer inject code into the exported spec. Uploads come only from `caw/fixtures`.
- The `.mcp.json` entry pins npx to this version and looks for an installed copy only up to the repository root. A session marker counts only with a token kept outside the project. Apply change refuses `node_modules` and `.git` at any depth, agent instruction files (`CLAUDE.md`, `AGENTS.md`, `.cursor/` …) and CI files. `init` ignores `caw/.explore.json`, `role login` ignores `caw/.auth/`, explore drops the query from the start path.
- The release workflow publishes from a separate job that alone holds the OIDC token, with npm 11.15.0 and install scripts off; CI runs with read-only permissions. The docs say that `caw.config.json` and recordings (`check`, `remember`) are executable configuration to review like code.

## [1.0.0-rc.2] - 2026-11-18

### Changed
- The workbench title is one sentence with the test: "Claude records morning-errand", "Checking morning-errand without Claude", "morning-errand up to S3, then the window is yours". Next to it only what the project leaves open: the environment when there are several (a production environment always), the role when there are several, your local build only under an overlay.
- The tool is called caw in every text, as the command; caw-ai is only the npm package (`npm i -D caw-ai`, `npx caw-ai mcp`). The status reads "caw working", recordings start with "Written by caw".

## [1.0.0-rc.1] - 2026-11-18

First release candidate for 1.0.

### Added
- Test plans as YAML in `caw/tests/` (steps `S<n>` with title, action and one expected result) and recordings per step in `caw/recordings/`, written by the tool only.
- `caw record`: you demonstrate, describe a new test in the chat (each message keeps its page; clicks are not recorded), Claude follows the plan, or the Claude Code session records. Your messages are numbered H1, H2 …; the plan says in `heard` what became of each, and the approval card shows your words with it; every recording ends with a plan you approve and a check run. `record <test>@S4` re-records from a step to the end.
- Recordings store native Playwright locators, one per target (`getByRole('button', { name: 'Save', exact: true })`, frames via `contentFrame()`), parsed without running code; ExtJS components also via the `extjs=` selector engine (`Ext.ComponentQuery`). Replay needs exactly one visible, uncovered match, tolerates two for a dialog transition, scrolls virtual lists and explains a missing target (frame missing, covered by a dialog, renamed).
- Actions `click`, `dblclick`, `fill`, `type`, `press`, `upload`, `download`; a demonstrated double-click is recorded as one `dblclick`, a file chosen from `caw/fixtures` as an `upload` (files from elsewhere are named, never copied). A plan reworded during recording keeps the checks already passed; only a changed expected result or order takes them back, and going back to it restores them.
- `caw run`: deterministic replay without Claude, with retries for flaky pages, learned network and effect baselines, and a split between test, application and environment failures. Several tests in a row (`run a b c`, `run --all`), JUnit output, CI mode (`--no-chat`, `--headless`, `--claude-timeout`, `--max-actions`).
- `caw open`: the app signed in with workbench and chat; `open <test>` replays the test and hands over the window, `open <test>@S4` stops at the entry of S4.
- Workbench: steps, the app under its own address and the chat in one window; key bar (F1 Open…, F5 Reload, F9 Pause, Esc Cancel, F2 Requests, F3 Console, F4 Steps, F6 Chat, F7 Theme, F8 App only, F10 Animations off).
- Fixing and developing in the chat: ask Claude, fix a step, get code advice to accept or reject; while developing Claude can use the page and propose code changes.
- Extensions outside the core, documented in `docs/extensions/`: the overlay (your local code over a deployed environment, per part from its code server or a build folder; `caw overlay status` and `overlay check`, `--overlay` on `run`, `record`, `open`) is active only with an `overlay` block in `caw.config.json`, otherwise help, validate, doctor and the MCP tools leave it out and `caw overlay`/`--overlay` name the page. ExtJS (`"framework": "extjs"`, written by `init` for a Sencha workspace) adds the `extjs=` locators, its quiet-page probe, message boxes, the Sencha watch as overlay source and the `extjs` guide topic.
- Setup: `init` (`--explore-only` only looks at the app), `validate`, `doctor`, `role` (`role login` stores an SSO session), `list`; the MCP server (`caw mcp`) lets your session set up projects, start runs and act as the agent.
- Agents: `local` (Claude Code with narrow tools), `docker` (isolated sandbox with firewall) and `session` (your Claude Code session); cost limits via `agent.model` and `agent.maxBudgetUsd`.
- Sign-in: login form, one-time codes, steps on an identity provider (`init --explore-only` suggests them from the provider's pages, identifier-first and one-time codes included), SSO via saved sessions; test users per role in `caw/.env` or the environment, filled in by hand.
- Network and safety: one request name (`POST /graphql mutation CloseTicket`, `json.<key>` for JSON-RPC) and one rule for what writes, with `reads` for requests that only read; pages navigate only to the app's hosts and `allowHosts` (`host-blocked`), while scripts, fonts, analytics and iframes may load from anywhere and are listed as third-party hosts whose errors are warnings; production hosts are unreachable from other environments, and a run on production sends no write requests (`write-blocked`); error pages count as evidence.
- Environment lifecycle: `start`, `stop`, `reset` and `ready` per environment with your own commands. `--start` starts an environment that doesn't answer and stops it at the end (already running: used, never stopped); `run` resets once before the first writing test, `--reset` before the first test, `--no-reset` never; error codes `env-start-failed`, `env-not-ready`, `env-reset-failed` and `env-unreachable`. Never on production.
- One language per project: caw's own texts follow the team language (`language`, if `de` or `en`) unless you choose your own with `CAW_LANG`; names from the app and the config stand in straight quotes in every language.
- Learning only on request: `run --learn` writes missing baselines and effects in every mode; with chat a passed run offers "Learn baselines" on its end card; otherwise a run changes no file. The mode line names environment, team language and whether the run learns.
- `caw export <test>`: the recorded test as a Playwright test (`<test>.spec.mjs`, `caw-support.mjs`, `playwright.config.mjs` with the list and HTML reporters) that runs without caw, with the recorded locators, dialog decisions, `remember` and placeholders.
- Claude Code setup through MCP only: `claude mcp add caw --scope project -- npx caw-ai mcp`. The server is named `caw`, tells Claude what caw is for and serves the guidance per topic with `caw_guide`. `caw_init` (`explore`, `write`, `offline`) and `caw_role` (`add`, `login`) set up the project from the session. `init` points an `npx` entry at the installed copy once caw is in `node_modules`.
- Native dialogs (alert, confirm, prompt, beforeunload): the answer is recorded on the action that opens the dialog and replayed; unexpected dialogs are dismissed and reported (`dialog-unexpected`), missing ones too (`dialog-missing`). The chat asks while you demonstrate; Claude arms the answer with `caw agent dialog`.
- Actions `hover` and `dragTo`.
- Dates as `{{date±n}}` in the browser's locale and `{{isoDate±n}}`; `remember` takes values of any length, short ones replaced only where they cannot be other text.
- The workbench shows the app at the recorded viewport, scaled down to fit, while caw replays; once the window is handed over the app fills the pane.
- The step list has a heading "Run" ("Durchführung") above the test's steps, between preparation and wrap-up.
- Themes as packages: built-in `studio` (default), `terminal`, `raster` and `glas`, each with a dark and a light mode; own themes next to `prefs.json` (their `light` block holds the light colours), `caw theme` with `use`, `mode` and `check`. F7 in the workbench picks the theme and switches between dark and light at once, a mode the theme lacks greyed out; it never edits a theme, own themes are folders written by hand. The terminal keeps the dark colours. Small labels use the text font in every theme, because the pixel font VT323 is never pixel-exact at small sizes; it stays for the logo and, in `terminal`, for large type.
- The command is `caw` (package `caw-ai`, `npx caw …` once installed). Claude's browser commands live under `caw agent` and are not in the human help. Durations carry their unit (`--step-timeout 30s`, `--claude-timeout 60m`); `--env` picks the environment, `--explain` lets Claude explain failures unasked, `--max-actions` limits Claude. Old command and flag names are refused with their new name.
- User interface, CLI, messages and reports in English and German.
